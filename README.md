## 相较原版的玩法变化

蛊真人并不是在原版角色模板上单纯增加一批新卡，而是在《杀戮尖塔 2》的基础战斗规则之上，加入了一套独立的 **蛊虫侧牌堆、多层资源、转数成长与炼蛊系统**。原版的能量、抽牌、格挡、易伤等规则仍然存在，但构筑与战斗节奏会明显不同。

| 方面 | 原版常规玩法 | 蛊真人 Mod |
| --- | --- | --- |
| 战斗牌组 | 主要围绕抽牌堆、手牌、弃牌堆循环 | 额外拥有独立的蛊存放牌堆与蛊恢复堆 |
| 主要资源 | 以原生能量为核心 | 原生能量 + 元气 + 光辉 + 仙元 |
| 卡牌成长 | 通常每张牌只有一次升级 | 蛊虫除升级外，还有一转至九转的长期成长 |
| 角色成长 | 主要依赖卡牌、遗物与局内奖励 | 增加贯穿整局的修为与空窍境界 |
| 篝火 | 休息、升级等原版选项 | 增加升炼与合炼 |
| 关键牌使用 | 必须先抽到手中才能正常使用 | 通过“催动”从蛊牌堆中主动选择蛊虫 |
| 高阶资源 | 无对应的独立高阶体系 | 六转后进入仙蛊与仙元体系 |
| 合成玩法 | 通常没有牌间配方合成 | 可通过合炼配方把材料蛊炼成新蛊 |
| 流派联动 | 依各原版角色机制而定 | 当前最完整的是光道的折光、光辉与照破 |
| 多人唯一性 | 按原版牌组与唯一规则处理 | 同名六转及以上仙蛊在全队中唯一 |

### 1. 蛊虫不是普通手牌

方源的蛊虫在战斗开始后会从普通牌组循环中分离，进入独立的 **蛊存放牌堆**。因此蛊虫并不依赖正常抽牌才能使用。

角色通过基础牌 **“催动”** 来调用蛊虫：

> 支付 1 点原生能量 → 从蛊存放牌堆选择一张可用蛊虫 → 自动打出该蛊虫。

因此一次蛊虫行动通常同时涉及两层成本：

- “催动”消耗的原生能量；
- 蛊虫自身消耗的元气，六转以上仙蛊还要额外支付仙元。

这使角色更像拥有一个可以主动检索的“蛊虫技能栏”，而不是完全依靠抽牌决定本回合能否使用关键能力。

为了让“不进入抽牌循环”仍然保有构筑代价，蛊虫永久牌组容量为 **10 张**。奖励、商店、合炼与转换都会在加入新蛊虫前检查容量；等量替换不会额外占用容量。

### 2. 蛊虫拥有使用次数与恢复周期

蛊虫拥有独立的可催动次数。次数耗尽后不会进入普通弃牌堆，而是进入 **蛊恢复堆**。

当前实现中，每张蛊虫在耗尽时记录自己的恢复回合：

> **耗尽回合 + 2。**

例如第2回合耗尽，会在第4回合开始时恢复；恢复后重新充满催动次数并返回蛊存放牌堆。

因此蛊虫的循环更接近“带使用次数和冷却的技能”，而不是原版常规的“抽到 → 打出 → 弃置 → 洗牌”循环。

### 3. 新增可跨回合经营的元气

元气是独立于原生能量的战斗资源。

- 第一回合拥有 5 点元气；
- 从第二回合开始，每回合回复 2 点；
- 元气不会在回合结束时清空；
- 上限随空窍境界提高：

| 空窍境界 | 元气上限 |
| --- | ---: |
| 一转 | 5 |
| 二转 | 7 |
| 三转 | 10 |
| 四转 | 14 |
| 五转 | 19 |
| 六转及以上 | 25 |

由于元气可以跨回合保留，玩家可以主动减少当前回合的蛊虫催动，为之后的爆发积攒资源。这与原版“主要围绕当回合能量分配”的思路有明显区别。

### 4. 修为与空窍让角色在整局持续成长

方源拥有独立的空窍境界，从 **一转一路成长到九转**。

一至五转阶段，战斗胜利给予修为：

- 普通战：+1 修为；
- 精英战：+3 修为；
- Boss 战：+5 修为。

一转至五转突破所需修为依次为 **1、2、3、4、5**。单场战斗最多完成一次大境界突破，低转阶段多出的修为会继续保留。

六转之后改为按胜利场数推进：

- 六转 → 七转：2 场胜利；
- 七转 → 八转：2 场胜利；
- 八转 → 九转：3 场胜利。

进入仙道后还会获得额外最大生命：

- 突破六转：+2 最大生命；
- 突破七转：+2 最大生命；
- 突破八转：+3 最大生命；
- 突破九转：+3 最大生命。

全部完成后共计增加 **10 点最大生命**。

因此战斗胜利本身不再只是获得金币、卡牌或遗物的手段，同时也是角色长期修炼成长的一部分。

### 5. 蛊虫自身也有一至九转

角色境界与蛊虫转数是两套相关但独立的成长系统。

蛊虫除了拥有普通的卡牌升级状态，还拥有 **一转至九转**。转数会改变蛊虫的伤害、格挡、照破、Replay 等效果，因此同名蛊虫在不同转数下可以表现出明显不同的战斗强度。

奖励中出现的蛊虫转数还会随爬塔楼层逐渐提高，高楼层更容易获得高转蛊虫。

这意味着蛊真人的卡牌成长并不止于原版常见的“基础版 → 升级版”，而是拥有贯穿整局的第二条成长轴。

### 6. 六转后进入仙蛊与仙元体系

蛊虫达到六转后成为 **仙蛊**，催动时除了元气外，还需要支付仙元。

| 仙蛊转数 | 单次催动仙元消耗 |
| --- | ---: |
| 六转 | 1 |
| 七转 | 2 |
| 八转 | 4 |
| 九转 | 8 |

角色达到六、七、八、九转后，每场战斗开始分别获得对应仙元：

| 角色境界 | 战斗开始获得 |
| --- | --- |
| 六转 | 青提仙元 2 单位 |
| 七转 | 红枣仙元 4 单位 |
| 八转 | 白荔仙元 8 单位 |
| 九转 | 黄杏仙元 16 单位 |

每一档仙元的初始总量恰好足够同境界仙蛊催动两次。

仙元牌可以保留在手中并分段消耗，余额用尽后才真正消耗整张牌。因此高转阶段除了元气，还需要规划每场战斗有限的仙元预算。

此外，同名六转及以上仙蛊遵循 **全队唯一** 规则：多人游戏中，整局所有玩家不能同时持有重复的同名仙蛊。

### 7. 篝火新增升炼与合炼

蛊真人在篝火中拥有两类额外成长行为。

#### 升炼

可以选择符合条件、尚未达到九转的蛊虫并提升其转数。蛊虫的“转数”与原版卡牌“升级”是两套独立状态，因此一张蛊可以同时拥有升级状态和更高转数。

#### 合炼

按照已实现配方消耗指定蛊虫，炼制新的蛊虫。结果蛊的转数取材料中的最高转数。

当前源码中已经完整落地的配方为：

> **月光蛊 + 小光蛊 + 小光蛊 → 月芒蛊**
>
> **月芒蛊 + 血气蛊 → 血月蛊**

因此构筑时会出现原版较少见的取舍：某张低阶牌可能不只是当前战力，也可能是之后合炼高阶蛊虫的重要材料。

### 8. 光道形成独立的出牌节奏

当前版本中，机制完成度最高的流派是 **光道**，核心围绕光辉、折光和照破展开。

#### 光辉

光辉上限为 **9 点**，并且不会在回合结束时消失。

#### 折光

当本回合当前打出的牌与上一张牌的类型不同，就会发生折光，例如：

> 攻击 → 技能 → 攻击

可以连续触发两次折光。

当当前打出的牌同时属于光道时，折光会获得 1 点光辉；每回合最多通过折光获得 3 点光辉。

因此光道会主动鼓励玩家交替使用攻击、技能、能力等不同牌型，而不是只围绕单一牌型连续出牌。

#### 耀化

当前实现中，耀化会弹出选择，由玩家决定是否支付光辉；同一次出牌序列的 Replay 沿用首段选择，不会重复支付。

#### 照破

照破是施加在敌人身上的专属减益。

每有一层照破，敌人下一次受到攻击牌的一段伤害时：

- 额外受到 3 点伤害；
- 消耗 1 层照破。

因此照破天然适合与多段攻击配合，形成“先叠照破，再使用高段数攻击集中爆发”的战斗思路。

### 9. 玉皮蛊提供“生成临时强牌”的玩法

玉皮蛊本身更偏向资源与牌生成。

催动后会获得敏捷，并生成一张比玉皮蛊自身 **高 1 转** 的“玄玉掌”进入手牌。

玄玉掌同时造成伤害并获得格挡，使用后消耗。高转玄玉掌还会逐步获得费用降低与 Replay，使玉皮蛊从单纯防御手段转变为持续制造“攻防一体临时牌”的核心工具。

### 10. 整体玩法差异

如果压缩成一句话：

> **原版主要围绕抽牌与当回合能量管理构筑牌组；蛊真人则通过普通牌作为操作指令，从独立蛊牌堆调用带次数与恢复周期的蛊虫，同时经营元气、光辉和仙元，并通过战斗修为、升炼与合炼让角色和蛊虫从一转一路成长到九转。**

最直接影响实战体验的三点是：

1. **关键蛊虫不需要正常抽到手中**，只要抽到“催动”即可主动选择；
2. **元气与光辉可以跨回合经营**，战斗更加重视资源留存和爆发窗口；
3. **角色和卡牌都会跨战斗持续升阶**，构筑目标不再只有拿牌、删牌和普通升级。

## 核心玩法

### 空窍与转数

- 角色通过空窍起始遗物保存转数和修为状态，当前实现范围为一转至九转。
- 一至五转使用战斗胜利获得的修为推进突破；六至八转按战斗胜利推进仙窍进度；九转是当前实现上限。
- 转数会写入模型状态并参与多人同步、存档恢复和卡牌复制。
- 空窍遗物会显示当前转数，并在篝火提供升炼与合炼选项。

### 蛊虫牌与蛊牌堆

- 蛊虫牌拥有一至九转，并使用独立的蛊存放牌堆与蛊恢复堆，不参与普通抽牌/弃牌循环。
- 蛊虫通过“催动”等入口从蛊存放牌堆中主动选择并自动打出。
- 每张蛊虫牌拥有独立可催动次数；规则按一次出牌序列计数，不会因 Replay 重复结算而重复计数。
- 蛊牌剩余催动次数归零后进入蛊恢复堆；每张牌从自身耗尽回合起独立冷却两回合。
- 蛊牌的奖励、商店、牌组唯一性和转换结果会统一检查，避免重复加入不允许的卡牌。
- 杀招牌与虚影牌只复用品阶和流派数据，不实现蛊虫接口；二者进入手牌并按普通手牌/弃牌堆规则流转，也不会成为仙蛊。

### 元气

元气是由 RitsuLib 次级资源系统管理的独立战斗资源，与游戏原生能量和其他资源分开计算。

- 初始元气为 5 点。
- 上限随空窍转数提升：一转 5、二转 7、三转 10、四转 14、五转 19、六转及以上 25。
- 第一回合使用初始元气，之后每回合开始回复 2 点，且不超过当前上限。
- 元气计数器会在蛊真人角色的战斗界面中显示，并定位在原生能量表盘的右上方。
- 计数器使用独立的 Godot 场景、旋转层和粒子特效；元气为 0 时自动切换为低亮度状态。
- 多人状态栏使用紧凑计数器显示队友元气，不改变其他角色的原生能量布局。

### 仙元与仙蛊

仙元牌可以在手牌中分段消耗，用于催动六转及以上的仙蛊：

- 青提仙元、红枣仙元、白荔仙元、黄杏仙元分别提供 2、4、8、16 点仙元单位。
- 六转、七转、八转、九转仙蛊单次催动分别消耗 1、2、4、8 点。
- 消耗会优先使用剩余单位较少的仙元牌；耗尽的牌进入消耗牌堆，未耗尽的牌继续保留。
- 同一出牌序列只在第一段结算仙元，Replay 后续段不会重复扣费。
- 同一局中相同身份的仙蛊遵循跨玩家唯一规则，与普通的“唯一”关键词分开处理。

### 升炼、合炼与杀招

- 升炼篝火可以选择符合条件的蛊虫牌，提高其转数；一次操作只执行一次，并支持多张牌选择。
- 合炼篝火根据代码中声明的配方消耗材料并生成结果牌，结果牌的转数由材料转数决定。
- 当前已经完整落地的合炼配方：
  - **月光蛊 + 小光蛊 + 小光蛊 → 月芒蛊**；
  - **月芒蛊 + 血气蛊 → 血月蛊**。
- 战斗中右键蛊虫牌堆的杀招推演流程、材料选择、费用计算与失败处理框架已经存在。
- **当前源码包尚未提供可实际匹配成功的具体 `ShaZhaoRecipe` 杀招配方，因此杀招系统目前应视为机制框架，而不是完整可玩的成品流派。**
- 若后续加入杀招配方，成功生成的杀招会进入普通手牌/弃牌体系，不属于蛊虫，也不会进入仙蛊唯一判定。

### 虚影、道痕与卡牌标签

- 虚影牌支持概率触发、攻击牌联动、力量倍率和额外闪耀效果；虚影保留在手牌中，但不属于蛊虫。
- 卡牌标签覆盖蛊道、光道、炎道、力道、偷道、木道、土道、杀道等道途。
- 关键词包括虚影、唯一、仙蛊以及一转至九转等转数提示。
- 部分卡牌支持轮播预览，悬停时可以查看当前轮播项。

## 卡牌设计

### 光道

#### 核心机制
以下机制仅光道卡牌可以获得、消耗或施加；公共调用入口会校验光道标签，非光道卡的误调用不会改变战斗状态。
##### 光辉

角色专属资源，上限为 **9点**，不会在回合结束时消失。

部分卡牌能够获得光辉，另一些卡牌可以消耗光辉发动更强效果。

##### 折光

当本回合打出的牌，与上一张牌的类型不同，便触发一次折光。

只有当前打出的牌是光道牌时才会获得光辉；上一张牌可以来自其他流派。

牌的类型包括：

- 攻击
    
- 技能
    
- 能力
    

每回合最多通过折光获得 **3点光辉**。

例如：

> 攻击 → 技能 → 攻击  
> 将连续触发两次折光。

回合开始后打出的第一张牌不会触发折光。

##### 耀化 X

耀化表示卡牌可以消耗光辉发动额外效果。

当光辉达到要求时，耀化牌会弹出“消耗光辉 / 保留光辉”的同步选择。选择保留时只结算基础效果；选择消耗时支付对应光辉并结算强化效果。Replay 会沿用首次选择，不会再次支付光辉。

###### 照破

施加于敌人的专属减益。

敌人每有一层照破，下一次受到攻击牌的单段伤害时：

- 额外受到3点伤害
    
- 移除1层照破
    

多段攻击可以连续消耗多层照破。

#### 力道（机制框架 / 规划内容）

> 当前源码包中尚未看到与下述力道设计完整对应的具体可玩卡牌实现；以下内容更适合作为机制规划说明，而不是当前版本已完成内容。


##### 力势

上限为 **12点**，回合结束时不会消失。

以下情况可以获得力势：

- 使用部分蓄力技能
    
- 打出高费攻击牌
    
- 主动损失生命
    
- 承受敌人的未被格挡伤害
    

每回合第一次因敌人攻击损失生命时，获得1点力势。

##### 发劲 X

带有“发劲”的牌在打出时，可以选择消耗X点力势，触发额外效果。

例如：

> 发劲3：伤害翻倍。

玩家可以拒绝发动发劲，将力势留给之后的杀招。

##### 兽力虚影

兽力虚影是一种战斗资源，最多同时拥有 **5道**。

打出攻击牌后：

- 消耗1道兽力虚影
    
- 虚影攻击同一目标，造成6点伤害
    

无论攻击牌造成一段还是多段伤害，每张攻击牌通常只会触发一道虚影。

兽力虚影造成的伤害不受力量影响，但可以受到易伤影响。

##### 搏命 X

主动失去X点生命，生命损失无视格挡，但不能使角色的生命降至0。

若当前生命不足以支付，便无法打出该牌。

## 战斗流程

每场战斗中的资源和蛊虫效果按以下顺序处理：

1. **战斗开始**：空窍系统按楼层标记开启新的战斗事务并重置仙元发放状态；重连或重复回调不会重复重置。
2. **初始抽牌前**：六转至九转时，第一次初始抽牌前分别将对应的青提、红枣、白荔或黄杏仙元牌加入手牌；发放使用可重试事务，确保断线恢复不会重复发牌。
3. **回合开始**：第一回合保留 5 点初始元气；从第二回合开始回复 2 点元气，元气不会超过当前转数上限；同时重置折光的上一张牌类型和本回合获取计数。达到各自的恢复回合时，蛊恢复堆中的蛊虫分别恢复催动次数并返回蛊存放牌堆。
4. **尝试出牌**：系统先执行原版可出牌判定，再检查蛊虫牌剩余可催动次数和实际元气费用。超过牌面限制或元气不足时，蛊牌、自动打出和 Replay 链均会被阻止。
5. **仙蛊支付**：六转及以上蛊虫在出牌序列第一段结算仙元。支付不足时出牌被拒绝；Replay 后续段不重复扣费。
6. **效果结算**：卡牌效果、蛊牌堆自动打出、虚影触发、光辉/折光/照破和元气变化按游戏原有战斗队列执行；出牌完成后更新催动次数与蛊牌堆状态。
7. **战斗胜利**：按普通战斗、精英战或首领战给予修为，提交转数推进和待完成突破，再执行遗物显示刷新等副作用。断线或房间重建后可以幂等恢复未完成步骤。

蛊真人的战斗流程由空窍起始遗物统一接入，因此手动出牌、蛊牌堆自动出牌、右键杀招推演和多人重连会使用同一套规则。杀招推演不再是一张系统卡：战斗中右键蛊虫牌堆，花费1点能量并按顺序逐张选择蛊虫材料即可开始推演；配方成功还必须支付材料平均有效元气消耗的两倍。

- Mod 依赖 STS2-RitsuLib；运行库或游戏 API 更新后，补丁目标可能需要重新适配。

## 安装

### 前置条件

1. 《杀戮尖塔 2》0.110.0 或兼容版本。
2. STS2-RitsuLib 0.5.4 或兼容版本。
3. 从 Releases 获取本 Mod 的 DLL、PCK 和 GuZhenRen.json。

### 安装步骤

1. 将 STS2-RitsuLib 安装到游戏的 mods 目录。
2. 将 GuZhenRen.dll、GuZhenRen.pck 和 GuZhenRen.json 放入游戏的 mods/GuZhenRen 目录。
3. 启动游戏并确认 Mod 加载顺序满足依赖关系。

## 从源码构建

项目使用 Godot .NET SDK 和 .NET 9。

1. 将 local.props.template 复制为 local.props。
2. 在 local.props 中填写本机的 Sts2Dir、Sts2DataDir 和 GodotExe。
3. 运行：

    dotnet restore
    dotnet build

默认构建会生成 GuZhenRen.dll、复制 Mod 文件，并通过 Godot 导出 GuZhenRen.pck。

只验证 C# 编译、不导出 PCK：

    dotnet build -p:RunPckExport=false

不复制到游戏目录：

    dotnet build -p:RunPckExport=false -p:CopyModOnBuild=false

构建前请关闭正在打开该项目的 Godot 编辑器、游戏进程和其他可能加载 sts2.dll 的进程。若 Publicizer 报告 sts2.dll 被占用，可先执行：

    dotnet build-server shutdown

然后关闭 Godot、MSBuild 和 VBCSCompiler 进程，再重新构建。

项目会显式排除本地 src/ 游戏源码和 .build/ 生成目录，避免它们被 SDK 当作 Mod 源码编译。

### 本地验证

完整构建会同时编译 C#、导出 PCK 并复制到游戏 Mod 目录：

    dotnet build GuZhenRen.sln

也可以单独用 Godot 无界面实例化 UI 场景，验证资源路径、脚本加载和节点初始化：

    Godot --headless --path . --quit-after 5 res://GuZhenRen/scenes/ui/nodes/GuZhenRen_energy_counter.tscn
    Godot --headless --path . --quit-after 5 res://GuZhenRen/scenes/ui/nodes2/GuZhenRen_energy_counter2.tscn

构建和场景冒烟测试已在 Godot 4.5.1 .NET、.NET 9 与游戏 v0.110.1 环境中验证。
