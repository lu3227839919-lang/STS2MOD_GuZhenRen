# GuZhenRen / 蛊真人

《杀戮尖塔 2》的非官方同人 Mod，以方源为主角，围绕蛊虫转数、空窍修为、元气和仙元催动构建独立的战斗与成长系统。

## 核心玩法

### 空窍与转数

- 角色通过空窍起始遗物保存转数和修为状态，当前实现范围为一转至九转。
- 一至五转使用战斗胜利获得的修为推进突破；六至八转按战斗胜利推进仙窍进度；九转是当前实现上限。
- 转数会写入模型状态并参与多人同步、存档恢复和卡牌复制。
- 空窍遗物会显示当前转数，并在篝火提供升炼与合炼选项。

### 蛊虫牌与蛊牌堆

- 蛊虫牌拥有一至九转，并使用独立蛊牌堆与蛊弃牌堆。
- 每张蛊虫牌可以声明每回合最多催动次数；规则按一次出牌序列计数，不会因 Replay 重复结算而重复计数。
- 蛊牌剩余催动次数归零后会以原版动画进入蛊弃牌堆，并在下一回合恢复可用时返回蛊牌堆。
- 蛊牌的奖励、商店、牌组唯一性和转换结果会统一检查，避免重复加入不允许的卡牌。
- 杀招牌复用部分转数接口，但不被视为蛊虫，也不会因此成为仙蛊。

### 元气

元气是由 RitsuLib 次级资源系统管理的独立战斗资源，与游戏原生能量和其他资源分开计算。

- 初始元气为 5 点。
- 上限随空窍转数提升：一转 5、二转 7、三转 10、四转 14、五转 19、六转及以上 25。
- 第一回合使用初始元气，之后每回合开始回复 2 点，且不超过当前上限。
- 元气计数器会在蛊真人角色的战斗界面中显示。

### 仙元与仙蛊

仙元牌可以在手牌中分段消耗，用于催动六转及以上的仙蛊：

- 青提仙元、红枣仙元、白荔仙元、黄杏仙元分别提供 2、4、8、16 点仙元单位。
- 六转、七转、八转、九转仙蛊单次催动分别消耗 1、2、4、8 点。
- 消耗会优先使用剩余单位较少的仙元牌；耗尽的牌进入消耗牌堆，未耗尽的牌继续保留。
- 同一出牌序列只在第一段结算仙元，Replay 后续段不会重复扣费。
- 同一局中相同身份的仙蛊遵循跨玩家唯一规则，与普通的“唯一”关键词分开处理。

### 升炼、合炼与杀招

- 升炼篝火可以选择符合条件的蛊虫牌，提高其转数；一次操作只执行一次，并支持多张牌选择。
- 合炼篝火根据代码中声明的配方消耗材料并生成结果牌，结果牌的转数由材料转数决定。
- 杀招推演可以按顺序选择材料，匹配配方时生成杀招；不匹配时会按规则自动打出材料牌，并处理能量不足的反噬。
- 杀招拥有独立的配方注册和合成流程，不进入普通蛊虫的仙蛊唯一判定。

### 虚影、道痕与卡牌标签

- 虚影牌支持概率触发、攻击牌联动、力量倍率和额外闪耀效果。
- 卡牌标签覆盖蛊道、光道、炎道、力道、偷道、木道、土道、杀道等道途。
- 关键词包括虚影、唯一、仙蛊以及一转至九转等转数提示。
- 部分卡牌支持轮播预览，悬停时可以查看当前轮播项。

## 战斗流程

每场战斗中的资源和蛊虫效果按以下顺序处理：

1. **战斗开始**：空窍系统按楼层标记开启新的战斗事务，重置本场免费催动和仙元发放状态；重连或重复回调不会重复重置。
2. **初始抽牌前**：六转至九转时，第一次初始抽牌前分别将对应的青提、红枣、白荔或黄杏仙元牌加入手牌；发放使用可重试事务，确保断线恢复不会重复发牌。
3. **回合开始**：第一回合保留 5 点初始元气；从第二回合开始回复 2 点元气，元气不会超过当前转数上限。
4. **尝试出牌**：系统先执行原版可出牌判定，再检查蛊虫牌本回合已催动次数。超过牌面限制时，蛊牌、自动打出和 Replay 链均会被阻止。
5. **仙蛊支付**：六转及以上蛊虫在出牌序列第一段结算仙元。支付不足时出牌被拒绝；Replay 后续段不重复扣费。
6. **效果结算**：卡牌效果、蛊牌堆自动打出、虚影触发和元气变化按游戏原有战斗队列执行；出牌完成后更新空窍相关战斗状态。
7. **战斗胜利**：按普通战斗、精英战或首领战给予修为，提交转数推进和待完成突破，再执行遗物显示刷新等副作用。断线或房间重建后可以幂等恢复未完成步骤。

蛊真人的战斗流程由空窍起始遗物统一接入，因此手动出牌、蛊牌堆自动出牌和多人重连会使用同一套规则。

## 多人和兼容性

- 空窍、转数、仙元和牌组唯一状态使用可保存模型状态，并参与多人确定性处理。
- 篝火选项、牌组选择、牌堆自动打出和卡牌转换包含针对 0.110 API 的同步与确认补丁。
- 商店、奖励、牌组和卡牌预览会使用统一的唯一性与合法性检查。
- 本地化兼容补丁为关键词、遗物选项、卡牌描述、角色名称和旧能量图标语法提供回退。
- Mod 依赖 STS2-RitsuLib；运行库或游戏 API 更新后，补丁目标可能需要重新适配。

## 安装

### 前置条件

1. 《杀戮尖塔 2》0.110.0 或兼容版本。
2. STS2-RitsuLib 0.5.2 或兼容版本。
3. 从 Releases 获取本 Mod 的 DLL、PCK 和 GuZhenRen.json。

### 安装步骤

1. 将 STS2-RitsuLib 安装到游戏的 mods 目录。
2. 将 GuZhenRen.dll、GuZhenRen.pck 和 GuZhenRen.json 放入游戏的 mods/GuZhenRen 目录。
3. 启动游戏并确认 Mod 加载顺序满足依赖关系。

## 从源码构建

项目使用 Godot .NET SDK 和 .NET 9。

1. 将 local.props.template 复制为 local.props。
2. 在 local.props 中填写本机的 Sts2Dir、Sts2DataDir 和 GodotExe。
3. 运行：

    dotnet restore
    dotnet build

默认构建会生成 GuZhenRen.dll、复制 Mod 文件，并通过 Godot 导出 GuZhenRen.pck。

只验证 C# 编译、不导出 PCK：

    dotnet build -p:RunPckExport=false

不复制到游戏目录：

    dotnet build -p:RunPckExport=false -p:CopyModOnBuild=false

构建前请关闭正在打开该项目的 Godot 编辑器、游戏进程和其他可能加载 sts2.dll 的进程。若 Publicizer 报告 sts2.dll 被占用，可先执行：

    dotnet build-server shutdown

然后关闭 Godot、MSBuild 和 VBCSCompiler 进程，再重新构建。

项目会显式排除本地 src/ 游戏源码和 .build/ 生成目录，避免它们被 SDK 当作 Mod 源码编译。

## 当前限制

- 灾劫和十转内容尚未实现；九转是当前修行上限。
- 药水池已注册，但当前没有专属药水内容。
- 部分美术资源仍是占位或需要在实际游戏中确认显示效果。
- 项目能通过本地构建和 PCK 导出，但完整流程仍需在真实游戏环境中验证。
